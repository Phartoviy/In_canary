## 🔍 Что такое Canarytokens

**Canarytokens** — это сервис для создания специальных токенов-маркеров, которые срабатывают при определённом действии, например при открытии ссылки.

В рамках данной инструкции используется тип:

### `Web bug`

Этот тип создаёт уникальную ссылку.  
Если по ней происходит обращение, сервис отправляет уведомление на указанный email.

---

## 🎯 Когда использовать

Подход может применяться для:

- проверки контролируемого канала связи;
- тестирования внутренних процессов безопасности;
- фиксации факта открытия переданной ссылки;
- анализа событий в рамках согласованной проверки.

> [!IMPORTANT]
> Используйте такой механизм только в пределах своих систем, своих процессов или в рамках явно разрешённого тестирования.

## ⚡ Быстрый старт

1. Создать отдельную почту для уведомлений.
2. Открыть сайт Canarytokens.
3. Выбрать тип токена **Web bug**.
4. Указать email и имя токена.
5. Сгенерировать ссылку.
6. Отправить ссылку в проверяемый канал.
7. Ожидать уведомление до **7 дней**.

## 🪜 Пошаговая инструкция

### Шаг 1. Создание отдельной почты

Создайте отдельный email, который будет использоваться только для уведомлений.

**Рекомендации:**

- не использовать основной рабочий ящик;
- проверить папку «Спам»;
- хранить доступы в безопасном месте;
- выбирать нейтральное и понятное имя почты.

**Пример:**

`monitor.example@mail.com`

---

### Шаг 2. Переход на сайт Canarytokens

Откройте страницу:

<https://canarytokens.org/nest/>

После этого станет доступен интерфейс создания токенов.

---

### Шаг 3. Выбор типа токена

Выберите тип:

## `Web bug`

Он подходит для проверки факта открытия ссылки и отправки уведомления на email.

---

### Шаг 4. Заполнение параметров

При создании токена укажите:

#### Email для уведомлений

Адрес, на который будут приходить письма о срабатывании.

**Пример:**

`monitor.example@mail.com`

#### Текст сообщения / имя токена

Название должно быть понятным и уникальным.

**Примеры:**

- `Проверка канала связи 1`
- `Контрольная ссылка`
- `Канал_A_июль`
- `Тест_почта_внутренняя`

> [!TIP]
> Если планируется несколько проверок, называйте токены так, чтобы по письму сразу было понятно, к какому сценарию относится срабатывание.

---

### Шаг 5. Генерация ссылки

После заполнения полей сервис сформирует уникальную ссылку.

Именно она будет использоваться как токен для проверки канала связи.

---

### Шаг 6. Отправка ссылки в проверяемый канал

Направьте полученную ссылку в тот канал связи, который необходимо проверить.

**Варианты использования:**

- в тексте сообщения;
- в тестовой переписке;
- в рамках контрольной отправки;
- как часть согласованного сценария проверки.

---

### Шаг 7. Ожидание уведомления

После отправки ссылки нужно дождаться возможного срабатывания.

### Рекомендуемый срок наблюдения: **7 дней**

В течение этого периода необходимо отслеживать входящие письма на указанный email.

---

## 📨 Какие данные приходят в уведомлении

При срабатывании токена на почту обычно приходит письмо со следующими данными:

- **время события**;
- **IP-адрес** источника;
- **примерное местоположение**;
- дополнительные технические сведения.

### Это позволяет понять

- был ли переход по ссылке;
- когда это произошло;
- откуда примерно пришёл запрос;
- соответствует ли событие ожидаемому сценарию.

---

## 🧠 Как интерпретировать результат

### Если уведомление пришло

Это означает, что ссылка была активирована.

Проверьте:

- соответствует ли время ожидаемому периоду;
- известен ли IP-адрес;
- совпадает ли местоположение с предполагаемым;
- не указывает ли событие на нежелательную передачу информации.

### Если уведомление не пришло

Это может означать, что:

- ссылка не была открыта;
- сообщение не дошло;
- токен был заблокирован фильтрами;
- получатель не перешёл по ссылке;
- срока наблюдения оказалось недостаточно.

## ✅ Практические рекомендации

### 1. Используйте отдельный токен для каждого канала

Если проверяется несколько каналов связи, создавайте отдельный токен для каждого из них.

### 2. Называйте токены понятно

Хорошее имя токена помогает быстро понять, что именно сработало.

### 3. Ведите журнал проверок

Можно использовать простую таблицу:

| Дата создания | Название токена | Канал отправки | Срок наблюдения | Результат |
|---|---|---|---|---|
| 04.07.2026 | Канал_A_июль | Email | 7 дней | Ожидание |

### 4. Проверяйте папку «Спам»

Иногда письма от сервиса попадают туда.

### 5. Не смешивайте сценарии

Лучше запускать одну проверку — один токен.

---

## ⚠️ Ограничения

Следует учитывать особенности интерпретации таких событий:

- IP-адрес не всегда указывает на конкретного человека;
- геолокация определяется приблизительно;
- запрос может проходить через VPN, прокси или корпоративный шлюз;
- некоторые почтовые клиенты и системы защиты могут автоматически открывать ссылки;
- возможны ложные срабатывания.

> [!WARNING]
> Уведомление о срабатывании следует рассматривать как **сигнал для анализа**, а не как окончательное доказательство личности пользователя.
